# SnuffleStudy V3.4 Two-Account QA Script

**Purpose:** the manual QA pass for `docs/implementation_plans/V3.4_Implementation_Plan.md`'s
Task 9 — every social/accountability surface that can only really be proven with real, independent,
signed-in accounts clicking through the actual extension, not just at the data/authorization layer.
It is a **human step**: no agent session should attempt to execute this script, sign into anything,
or redeploy the Edge Functions below — those need live write access this repo's automation
deliberately doesn't have.

**Why this is a new file, not an extension of `docs/qa/V3.2_Two_Account_QA_Script.md`:** that
document's own header says to reuse it, not fork a new copy per release, and V3.3 followed that
(items 10–20 were appended in place). V3.4 breaks that pattern deliberately: it drops
`friend_groups`/`group_memberships`/`unlock_requests`/`temp_passcode_requests`/`session_end_requests`
outright and deletes `UnlockRequestPanel.tsx`/`TempPasscodePanel.tsx`/`SessionEndRequestPanel.tsx`/
`FriendGroupPanel`'s old "List members"/"Leave" UI entirely — most of that script's items 1, 2, 3, 5,
and 9 reference components, tables, and flows that no longer exist, not just copy that changed. This
script is self-contained for V3.4. Items untouched by V3.4 (daily digest visibility, Study Room A/V
mechanics, the core account-deletion Storage/Auth-Admin plumbing) aren't re-walked here — nothing in
this version touched them; re-run the old script's items 6 and 7 separately if you want that
coverage refreshed, or fold both scripts back into one canonical document later if that's preferred
going forward. That's a call for whoever runs this next, not decided here.

## 8. Nudges: Written + Audio unified, one friend picker, independent cooldowns (Task 8)

Covers: the merged "Send a nudge" section and the two ~60-second cooldowns actually being
independent of each other (the core new behavior — under the old single shared column, an audio send
would have been blocked by an active written cooldown; it should not be now).

**Read this before starting — a freshly-connected friend pair cannot nudge each other at all, by
design:** `friendship_settings.send_live_nudges`/`receive_live_nudges` both default to `false` (a
deliberate V2 privacy-by-default decision, migration `20260815000027` — every new connection starts
fully opted-out on the nudge axis, symmetric with the five sharing toggles, which also default off).
This is **not** a V3.4 regression and not something this version changed — but it means step 0 below
is not optional. Skipping it reproduces exactly the failure this note exists to prevent: attempting
a send with untouched defaults is flatly rejected by RLS (`new row violates row-level security
policy for table "nudges"`, confirmed directly against the live project), which looks identical from
the UI to "nothing arrived," for both written and audio.

0. As **Account A**: Settings → Friends → find B → turn ON **"I may send this friend a live
   nudge"**. As **Account B**: Settings → Friends → find A → turn ON **"This friend may send me a
   live nudge"**. Both sides, both directions — sending needs the sender's own `send_live_nudges`
   toward the recipient AND the recipient's own `receive_live_nudges` toward the sender.
1. As **Account A**, go to the top-level **Friends tab → "Send a nudge"** section. Confirm **one**
   friend picker (not two separate ones for written vs. audio) and a **Written / Audio** toggle.
2. With B selected and Written mode active, send a written nudge from the message catalog. Confirm
   it arrives in B's actual open UI.
3. Immediately try sending another **written** nudge to B. **Expected:** blocked (cooldown active —
   however this surfaces in the UI, confirm it doesn't send a second time).
4. Immediately switch to **Audio** mode and send an audio nudge (record or use the recorder) to B.
   **Expected: succeeds** — this is the behavior that would have been wrongly blocked before this
   task (single shared cooldown column). Confirm B receives it.
5. Immediately try a second **audio** nudge to B. **Expected:** blocked (its own, separate cooldown).
6. Wait ~60+ seconds. Retry both written and audio to B. **Expected:** both succeed again.
7. As **Account B**, go to Settings → Friends → toggle **"This friend may send me a live nudge"**
   off for A. As **Account A**, try both a written and an audio nudge to B. **Expected: both blocked**
   — confirms the shared toggle gates both modes, only the cooldowns are separate. Turn the toggle
   back on afterward.
