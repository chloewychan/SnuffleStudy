# SnuffleStudy V4.2 Two-Account QA Script

**Purpose:** the manual QA pass for `docs/implementation_plans/V4.2_Implementation_Plan.md`'s
Task 14 — this is a **re-skin** release ("replace every hand-rolled presentation component ... with
its `frontend-backup` equivalent, keeping 100% of the existing data layer intact," per the plan's
own Goal), not a new backend surface. Every `sendMessage()` call, every message type, and every
piece of application logic is unchanged from v4.1 — only the markup and CSS changed. This script is
therefore about **fidelity and integration**, not new-feature correctness: does the re-skinned
sidebar actually look like `frontend-backup`'s design, and does everything still work end to end
now that it's wired through new markup. It's still a **human step** — no agent session should
attempt to execute this script or sign into anything.

**What's already verified and does NOT need re-checking here:** `docs/reports/v4.2/task-14-
report.md` covers the full programmatic pass — clean `tsc`, 929/929 tests, a clean production
build, a full asset-path audit (one real gap found and fixed — see below), a full old-classname
audit (one real gap found and flagged, not fixed — see below), the join-by-code-removal
confirmation (still clean), a direct read of both undesigned surfaces
(`RequestUnlockForm.tsx`/the delete-account dialog) confirming they're built entirely from the
shared design system, and a direct-code trace confirming Header/TabBar mount exactly once across
all four tabs. This script is about what a build/test run and a grep genuinely cannot confirm:
does it look right, and does it work with two real accounts, a real browser, and real permission
prompts.

## Known, flagged limitations — not bugs to re-discover

Read this section first. Every item below was already found and explicitly logged by the
implementation tasks (or by Task 14's own automated pass) — none of them need re-reporting if you
hit them below. If you find something that looks like a defect and it's **not** on this list,
that's a real find — log it as a Fail on the relevant item.

1. **Nudge Vault's "Edit" icon on written nudges does nothing.** (Task 10) No
   `NUDGE_VAULT_TEXT_UPDATE` message exists in the backend at all — the icon renders (so you'll see
   it in item 4 below) but clicking it is a deliberate no-op, not a broken button. This is the one
   item the plan's own Whole-version Definition of Done names as staying flagged rather than
   resolved.
2. **The persistent footer area (below the tab content, holding the Study Room footer and/or the
   Nudges & Unlock Requests footer) may show a visible tan/beige border and cream background band
   that doesn't match the rest of the new pink-and-cream design.** (Task 14's own audit) The
   wrapper `<div>` that stacks these two footers was never re-skinned by any task — it still uses
   the pre-v4.2 visual styling (old padding/border-color tokens) underneath the new-design footer
   cards inside it. **Please specifically eyeball this in item 1 (visual tour) and item 2 (Study
   Room)** and describe what you actually see — this needs a real screenshot-level judgment call
   that no automated check can make, and confirming how bad it looks (if at all) will decide
   whether it needs a follow-up task before merge.
3. **Text in a few places (Friend Options popup's checkboxes, the three Settings General-box
   sub-sections, the History box's expanded event log) may render in a plain sans-serif font
   (Arial-ish) instead of the design's intended Nunito.** (Task 1, confirmed still open by Task 14)
   The Nunito webfont was never self-hosted — this is a font-family fallback, not a layout bug.
   Everything should still be legible and correctly laid out; only the letterforms will look
   generic in those specific spots.
4. **The header's rightmost icon (a plain "×"-style close icon next to Refresh) does nothing when
   clicked.** (Task 2) Deliberate — nothing in the current app has an action for it yet.
5. **The Study tab's "Join study room" button reads exactly that (lowercase "study room"), not
   "Join Study Room."** (Task 5) Deliberate, not a copy typo — kept this way on purpose so it can
   never be confused with the deleted join-by-code feature's old button text. Not a bug.
6. **During an active session, if you trigger the "media permission" error banner (e.g. by denying
   camera/mic access), its "Open a tab to grant access" button looks like a plain, unstyled browser
   button** (grey, no rounded corners, doesn't match the rest of the page). (Task 6) Pre-existing,
   not rebuilt in this version — no design frame exists for this specific error state yet.
7. **In a friend's Options popup, "Remove Friend" sits slightly closer to the checkboxes above it
   than the original design shows** (a minor nesting/spacing difference). (Task 9) Cosmetic only —
   confirm the button still works; don't fail on the spacing itself.
8. **On the full Options page (opened via `chrome://extensions` → Details → Extension options, NOT
   the sidebar), the Settings view now shows two separate "camera & microphone" call-to-actions
   stacked near each other** — a new "Grant Camera & Microphone Access" button (which just re-opens
   this same Options page, redundantly) sitting right above the pre-existing, real camera/mic
   permission section. (Task 11) Both work independently; it's just visually redundant. Not a bug,
   don't fail on it — but please confirm both buttons still do something sensible (see item 5
   below).
9. **The quiet-hours row in Settings has a small checkmark icon after the two time fields that does
   nothing when clicked.** (Task 11) Deliberate — quiet-hours times save automatically as you type,
   there's no separate "confirm" step for this icon to represent.
10. **The History box's "From"/"To" date filters look like plain text boxes showing `YYYY-MM-DD`
    (e.g., typing/clicking shows a text cursor, not a calendar dropdown by default).** (Task 13,
    deliberate) This is intentional — confirm in item 5 below whether this reads as acceptable in
    a real browser (it's only been verified in an automated test environment, not visually).

## Prerequisites

1. **No new migrations, no new backend surface this version** — this is a pure re-skin. If your
   Supabase project is already current for v4.1, nothing further is needed.
2. **Two accounts, two real browser profiles** — Account A and Account B, already connected as
   friends (carry over from a previous QA run, or set up fresh via the Friends box → "Generate
   Invite Code" / "Add Friend" — note the button now reads "Generate Invite Code," not "Invite a
   friend," per the new design's copy). Real inboxes (email OTP sign-in).
3. **Build and load from `v4.2`:**
   ```bash
   cd snufflestudy
   git checkout v4.2
   npm install
   npm run build
   ```
   Load `snufflestudy/.output/chrome-mv3/` as an unpacked extension in each profile.
   - [ ] Extension loads with no console errors in either profile.
   - [ ] `npx vitest run` and `npm run compile` both pass locally before you start (already
     re-confirmed this session — 92 files / 929 tests, clean `tsc` — but worth a fresh check if any
     local changes have been made since).

## 1. Full visual tour — does it actually look like the new design (Plan step 1 / step 8)

This is the item no automated check can do: a human comparing the running extension against
`frontend-backup`'s intended look, not just confirming buttons work.

1. Open the side panel fresh. Confirm the **Header** (bunny mascot, "Log In" if signed out,
   refresh icon) renders once, and the **TabBar** below it (Bunny / Study / Friends / Settings)
   shows four tabs in the new pink/cream pill style, with the active tab visually distinct.
2. Click through all four tabs in order: **Bunny → Study → Friends → Settings**. Confirm:
   - The Header and TabBar **do not flicker, remount, or reset** on any tab switch (no visible
     "flash" of the mascot image reloading, no refresh-button state reset).
   - Each tab's content visually matches `frontend-backup`'s corresponding page (Bunny tab ≈
     `AboutTheBun`, Study tab ≈ `StudySessionSetupPanel`/`TaskVaultPanel`/`StudyRoomsPanel`,
     Friends tab ≈ `FriendPanel`/`NudgeVaultPanel`, Settings tab ≈
     `SettingsBody`/`AccountSettingsPanel`/`SessionHistory` all stacked) — same color palette
     (cream/pink/dimgray), same rounded-card look, same fonts (Pangolin headings, Shantell Sans
     body — see the "known limitations" list above for the one font that may not load correctly).
   - The active tab's highlighted/"selected" visual state is unambiguous at a glance on every tab.
3. Confirm the **Bunny tab** shows the bunny image and two independent name fields with their own
   save icons (not buttons with visible text) — a quick sanity check against
   `docs/reports/v4.2/task-3-report.md`'s claim that Save became icon-only.
4. Confirm the **Settings tab** shows three stacked sections (General, Account, History) with no
   old plain-HTML styling visible anywhere — compare specifically against known-limitation items 8
   and 9 above (expected, not a fail) versus anything else that looks visually broken (unexpected,
   is a fail).
5. **Specifically eyeball known-limitation #2** (the footer area's possible old-style border/
   background) here if you have an active nudge/request showing in the footer without joining a
   room yet — otherwise check it properly in item 2 below. Note in your own words how noticeable it
   is (barely visible vs. clearly clashing) — this judgment call matters for prioritizing a
   follow-up fix.

## 2. Study Room end to end (Plan step 2 / Decision 3)

1. As **Account A**: Study tab → Study Rooms box. Create a room (confirm the create-room field is
   labeled "Create Study Room," with an icon-only confirm button — no visible "Create room" text
   button). Select it from the list, click **"Join study room"** (note: this button intentionally
   reads lowercase "study room," not "Study Room" — see known-limitation #5, not a bug).
2. Confirm the **Study Room footer** appears below the tab content with the new design (room name
   heading, camera/mic icon toggles, video tiles, Nudge control) — and **specifically look at
   whether the area immediately around/behind this footer shows an odd tan border or
   mismatched cream background band** (known-limitation #2 — report what you see, don't auto-fail
   on it, but do describe it).
3. As **Account B**: join the same room. On A's side, confirm B's video tile renders and click it —
   confirm it visually toggles to a "selected" look (an outline/highlight), and that **your own
   ("You") tile is not clickable at all** (no visual hover/selected state, no cursor change).
4. With B's tile selected, pick a vault item from the dropdown and click **Nudge** — confirm it
   sends without error (full round-trip confirmed in item 3 below, on B's side).
5. Leave the room (as A). Confirm the footer disappears.
6. Re-open the **access popup** for a room you own (the options/gear icon next to a room you
   created, not one you were only invited to) — confirm:
   - It opens as an overlay/modal (a scrim behind a centered card with a close button and/or
     backdrop-click-to-dismiss).
   - It lists **only currently-invited friends**, each with a **remove (trash) icon** — confirm
     **there is no "add a friend to this room" control anywhere in this popup** (no `+`, no
     checklist of friends-not-yet-added, nothing resembling an invite toggle). This is Decision 3's
     core guarantee — a real Fail if you find any add-to-room affordance here.
   - Removing an invitee updates the list immediately, without closing the popup.
   - "Archive Study Room" removes the room from the list and closes the popup.

## 5. Settings — all three boxes (Plan step 4)

1. **General box — Tracking:** switch the tracking tier radio between its two options. Confirm the
   **real Chrome permission prompt** fires (a genuine browser-level dialog, not anything this app
   can render itself) when switching to the tier that needs it, and that revoking it also works.
   This is the one thing in this entire release that literally cannot be verified by any automated
   test — please confirm it explicitly, not just that the radio button's visual state changes.
2. **General box — Restricted Sites:** add a site via the input + check-icon, delete it via its own
   trash icon — confirm both persist after closing and reopening the side panel.
3. **General box — Passcode:** enter a new passcode with a mismatched confirmation field — confirm

4. **General box — Camera & Microphone:** click "Grant Camera & Microphone Access" — confirm it
   opens the full Options tab (a new browser tab/page), not an inline permission prompt (Chrome

   known-limitation #8 — the redundancy itself isn't a fail, but both controls needing to actually
   function is).
5. **Account box:** sign out and sign back in. Set/change a password (old password field should
