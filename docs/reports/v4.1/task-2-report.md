## What I built

- **`sidepanel/refresh/RefreshRegistryContext.tsx`** (new) — the registry exactly as specified in the plan: `RefreshRegistryProvider`, `useRegisterRefresh`, `useRefreshAll`, a `Set<() => void>` held in a ref so registration/unregistration never triggers a re-render of the provider itself. One deviation from the plan's literal snippet: typed `children` as `ReactNode` (imported via `type ReactNode` from `"react"`) rather than `React.ReactNode`, since this codebase never imports a default `React` binding anywhere (`jsx: "react-jsx"`, confirmed via `tsconfig.json` and a repo-wide grep) — `React.ReactNode` would have failed to compile as "cannot find namespace 'React'". This also matches the exact import style the plan's own Task 7 template (`StudyRoomSessionContext.tsx`) already uses for the same purpose, so it's consistent with where this codebase is headed, not just a local fix.

- **`sidepanel/SidePanelApp.tsx`** — minimal, surgical edit given the six-early-return shape described above: renamed the existing function body from `export function SidePanelApp()` to (unexported) `function SidePanelAppInner()`, and added a new thin `export function SidePanelApp()` that renders `<RefreshRegistryProvider><SidePanelAppInner /></RefreshRegistryProvider>`. Nothing inside the original body — none of the six branches, no JSX, no logic — was touched. This satisfies "wrap the return tree… outside any tab/session branching" literally: the provider sits above every branch and is never remounted by anything the branches do, while every one of the file's several `<Header />` mounts (no-session view, showFriendRequestPanel view, active-session view) ends up nested under the same single provider instance. Added one import (`RefreshRegistryProvider` from `./refresh/RefreshRegistryContext`) at the bottom of the existing import block. No other line in the file changed.

## Judgment calls

- **Wrapper-component split instead of touching all six `return`s.** Described in detail above. Chosen because it's strictly more surgical (a rename plus ~7 new lines) than editing six separate JSX blocks, it can't accidentally miss one of the six branches, and it produces the exact behavior the plan's Definition of Done and File-structure note both describe (provider never remounts across tab/session changes). It also happens to leave `SidePanelApp.test.tsx` untouched, since the exported `SidePanelApp` component's own behavior (render `<Header />` etc. eventually) is unchanged from any test's point of view — it just now does so through one extra layer.
- **`ReactNode` import instead of the plan's literal `React.ReactNode`.** Described above — required for the file to compile given this codebase's existing import conventions; functionally identical.
- **Added a CSS rule for the new button** even though the plan's own Deliverables section for this task doesn't mention CSS. Judgment call: an unstyled, unconditionally-visible button sitting in the header felt like an omission worth avoiding for near-zero cost, and it's a one-for-one copy of an existing, already-approved style rather than new design. Flagging in case a later reviewer would rather this task stay logic-only and have styling deferred.
