## Deviations from the plan's literal text (and why)

1. **Asset location: `snufflestudy/public/sidepanel/assets/`, not `snufflestudy/src/sidepanel/assets/` as the plan's Deliverables/File-Structure text says.** Verified empirically (baseline build before any changes): WXT only copies the project's `public/` directory verbatim to `.output/<target>/`; files under `src/` are not copied anywhere unless imported as ES modules through Vite's asset pipeline (which this codebase has zero existing examples of — only `chrome.runtime.getURL("...")` against `public/`-rooted paths, confirmed in `Header.tsx`, `animationRegistry.ts`, and `mediaPermissions.ts`). Putting the copied icons under `src/sidepanel/assets/` as literally specified would have made every `chrome.runtime.getURL("sidepanel/assets/...")` call resolve to a 404 in the actual packed build — exactly the "fails silently as a broken image" risk the plan itself calls out as the thing to avoid. This is corrected per the orchestrator's own instruction to verify the plan's claims against actual repo/build behavior rather than follow stale text. **Everywhere later tasks would write `sidepanel/assets/<file>` in a `chrome.runtime.getURL(...)` call, that is still the correct string** — only the on-disk source location differs from the plan's literal wording (`snufflestudy/public/sidepanel/assets/` instead of `snufflestudy/src/sidepanel/assets/`).
2. **Fonts: no remote `@import` carried forward, no new self-hosted Nunito webfont added.** frontend-backup's `global.css` never had real `@font-face` rules — only `@import url(https://fonts.googleapis.com/...)` for Pangolin, Shantell Sans, Nunito, and Material Icons. This project already self-hosts Pangolin and Shantell Sans as local WOFF2 files under the same family names (see `tokens.css`), so those two "just work" with the merged `--font-pangolin`/`--font-shantell-sans` variables — no action needed. Material Icons is entirely unused anywhere in frontend-backup's markup (grepped, zero hits) and was dropped rather than merged. **Nunito has no local `@font-face` anywhere yet** — `--font-nunito` falls back to `Arial, sans-serif` until a later task that actually renders Nunito-styled markup adds a self-hosted webfont for it, consistent with this project's self-hosting convention. This is flagged as an open item below, not silently guessed at.
3. **Added a mechanical type-only-import fix** to all 7 `ui/` `.tsx` files (see above) that wasn't named in the plan's Deliverables, because `npm run build` alone doesn't catch it (Vite/esbuild strips types without full checking) but `npm run compile` (`tsc --noEmit`) does, and it would otherwise surface as a compile error the moment any later task's file imports one of these primitives.
