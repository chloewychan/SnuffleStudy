## What was built

- **`messageRouter.ts`** / **`shared/messages.ts`**: `AUTH_SET_PASSWORD` and `AUTH_SIGN_IN_PASSWORD`, per the confirmed API shape above.
- **`SignInForm.tsx`**, restructured around an internal `Mode` state machine, per Decision 6 (the choice lives in the component, not a caller prop):
  - `"choice"` (entry): Create account / Sign in, with `onSkip` (when present) available here too.
  - **Create-account branch** (`"create-email"` → `"create-code"` → `"create-password"`): the existing `AUTH_REQUEST_OTP`/`AUTH_VERIFY_OTP` round trip, then — critically — `onSignedIn` is **not** called on a successful verify. The verified session is held in `pendingCreateSession` and a mandatory two-field password step follows; only a successful `AUTH_SET_PASSWORD` fires `onSignedIn`. The submit button's `disabled` condition is `authBusy || !password || password !== confirmPassword` — genuinely disabled (not just visually styled), not enabled until both fields are non-empty and match.
  - **Sign-in branch** (`"signin-choice"` → `"signin-password"` or `"signin-otp-email"` → `"signin-otp-code"`): two true peer options. "Sign in with a password" uses its own separate `signInEmail`/`signInPassword` state (deliberately not shared with the create-account branch's `email` field, so switching branches never leaks a partially-typed value between unrelated flows) and calls `onSignedIn` directly on a successful `AUTH_SIGN_IN_PASSWORD`. "Email me a code" is the unchanged OTP round trip, calling `onSignedIn` directly on verify — no password step tacked on, since the account already exists.
  - `onSkip` renders at every step in both branches (via a shared `skipButton` element), matching today's single-step behavior extended across the new multi-step flow.
- **`AccountPage.tsx`**: a new "Password" section — "set/change your password" for an already-signed-in user, using the same `AUTH_SET_PASSWORD` message and the same genuinely-disabled-until-matching submit condition. This is the recovery path for any account created before this feature shipped (no password yet) and the ordinary way to change a password later; explicitly documented as no longer the *primary* way a password gets set now that it's mandatory at signup.
- **`OnboardingWizard.tsx`**: confirmed zero diff — it renders `SignInForm` unchanged at the call-site level, exactly as Decision 6 predicts (the split lives entirely inside the shared component), and `onSkip` is passed through unchanged.
- **Collateral test fixes**, all mechanical and scoped to the one thing that changed (`SignInForm`'s signed-out entry state is now a "Create account"/"Sign in" choice, not a bare email field): `FriendGroupPanel.test.tsx`, `SessionEndRequestPanel.test.tsx`, `StudyRoomPanel.test.tsx`, `TempPasscodePanel.test.tsx`, `UnlockRequestPanel.test.tsx` — each had one assertion (`screen.getByLabelText("Email")`) updated to assert the new entry-state button instead, and `StudyRoomPanel.test.tsx`'s one full sign-in-flow test updated to navigate `Sign in` → `Email me a code` before reaching the same `AUTH_REQUEST_OTP`/`AUTH_VERIFY_OTP` assertions it had before (also updated its code literal from 6 to 8 digits, matching Task 2). No test's actual signed-out-gate behavior changed — this is the same class of collateral fix Task 1's report already documents for this run.
